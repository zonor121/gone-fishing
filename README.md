# Рыбалка
Запуск: `python server.py` (Python 3.8+, без зависимостей), затем http://localhost:8000.

## Подключение Supabase
1. В новом проекте Supabase откройте SQL Editor и выполните **весь** `db/supabase.sql`: таблицы, каталог, ограничения доступа и функцию `fishing_api`.
2. Скопируйте `.env.example` в `.env` в корне проекта. Укажите `SUPABASE_URL` и `SUPABASE_SECRET_KEY` (серверный Secret key из Settings → API Keys). Для старого ключа `service_role` поддерживается `SUPABASE_SERVICE_ROLE_KEY`. Публичные publishable/anon ключи не подходят.
3. Запустите `python server.py`. Проверка `/healthz` обращается к Supabase. При недоступной БД сервер не переключается незаметно на SQLite.

`.env` исключён из Git. Переменные окружения имеют приоритет над ним. Ключ используется только Python-сервером; браузер продолжает обращаться к `/api/*`. Supabase Auth не используется: существующие логины, PBKDF2-хеши и cookie-сессии сохранены. Таблицы закрыты для anon/authenticated, функция доступна только service_role. Покупки, уловы, задания и регистрация выполняются атомарно в PostgreSQL. День заданий теперь считается по UTC.

`db/supabase.sql` можно повторно выполнить без удаления данных. Исходник функций — `db/supabase_api.sql`; пересборка общего файла: `python tools/build_supabase_schema.py`.

**Старые данные SQLite не переносятся автоматически.** Подключение к Supabase создаёт отдельное хранилище. Не удаляйте исходную БД. Для проверки прежних сохранений задайте `DB_BACKEND=sqlite` и `DB_PATH` (по умолчанию `db/fishing.db`); старые миграции остаются доступны. Перед переключением рабочего сервера нужен отдельный перенос существующих аккаунтов и прогресса, если они есть.

## Регистрация и вход
У каждого игрока своё сохранение: деньги, наживка, улов, задания и достижения привязаны к аккаунту. При первом открытии сайт показывает экран входа — можно зарегистрироваться (логин 3–20 символов: буквы, цифры, точка, дефис, подчёркивание; пароль от 6 символов) или войти. Логин и пароль проверяет сервер (`auth.py`), пароль хранится только в виде PBKDF2-хеша со случайной солью.

Сессия живёт 30 дней: после входа сервер ставит HttpOnly-cookie `fishing_session` с токеном из таблицы `session`, поэтому прогресс ждёт игрока на любом устройстве после повторного входа. Кнопка «Выйти» в шапке гасит сессию.

API аккаунтов: `POST /api/register`, `POST /api/login`, `POST /api/logout`. Игровые методы (`/api/state`, `/api/cast`, `/api/buy`, `/api/catch`, `/api/quest/claim`, `/api/tutorial`) требуют активную сессию и работают только с её пользователем; `/api/config` и `/healthz` общедоступны. Погода и время суток — общие для всего мира, улов и деньги — личные.

**Переезд старого сохранения (только режим SQLite).** Раньше игра была одна на всех (`player.id=1`). При первом запуске новой версии это общее сохранение автоматически переезжает в аккаунт `fisherman` с паролем `fisherman` (сообщение об этом появится в логе сервера). Войдите под ним, чтобы продолжить прежний прогресс; для остальных игроков заведите личные аккаунты через регистрацию.

## Морская рыбалка
Лодка стоит 6 000 ₽ в магазине и навсегда открывает четвёртую локацию. Покупка сохраняется в выбранной БД, повторно платить не нужно. Морские виды: скумбрия, треска, морской окунь и тунец. Подходящие приманки и цены указаны в справочнике; новая приманка — креветка за 80 ₽.

Улов принимается сервером только после оплаченного наживкой заброса в доступной локации, не раньше чем через 12 секунд. Даже при мгновенном вываживании и каждом улове по максимальной пресноводной цене (350 ₽, форель), без расходов на приманку, стартовые 200 ₽ плюс 15 уловов за три минуты дают не более 5 450 ₽.

## Погода и время суток
Время суток (утро → день → вечер → ночь) сменяется автоматически каждые 3 минуты и показывается чипом над сценой. Погода (ясно, дождь, туман, ветер) меняется случайно каждые 2–4 минуты. Дождь снижает общую вероятность поклёвки, туман ухудшает видимость поплавка, ветер уводит заброс и сносит поплавок. Активность рыб зависит от условий: налим клюёт только ночью, форель — только в дождь, окунь — утром и вечером, плотва — утром и днём, тунец — днём. Метки активности есть в справочнике.

## Ежедневные задания, достижения, дневник
Каждый день генерируются три задания (день считается по серверу); прогресс растёт после каждого улова и считается сервером. Награда — деньги и запасы приманок, забирается кнопкой на вкладке «Задания».
Достижения: «Первый улов», «100 пойманных рыб», «Мастер моря» (поймать тунца), «Коллекционер» (все 12 видов). При открытии появляется уведомление.
Вкладка «Дневник» показывает суммарный улов, самую тяжёлую рыбу, счётчики и открытые виды; статистика обновляется после каждого улова. Всё сохраняется в Supabase между сессиями (либо в SQLite при явном `DB_BACKEND=sqlite`).

Проверки: `python tools/run_tests.py` (явно включает SQLite, временные БД; настоящий прогресс не затрагивается). Тесты клиента Supabase используют подмену транспорта, а не рабочую облачную БД.
Страницы `static/tests/*.html` сервер отдаёт только при `SERVE_TESTS=1`.

## Полноэкранный режим

Кнопка в правом верхнем углу сцены (или клавиша **F**) разворачивает рыбалку на весь экран; выход — той же кнопкой, **F** или **Esc**. Где Fullscreen API недоступен (iPhone), сцена разворачивается на всё окно браузера.

## Деплой на Render
1. Залейте проект в GitHub/GitLab (файл `db/fishing.db` в репозиторий не попадёт — см. `.gitignore`).
2. Render → **New + → Blueprint** → выберите репозиторий. Настройки возьмутся из `render.yaml`.
3. Сервис слушает `$PORT`, health check — `/healthz`, версия Python — `.python-version`.

**Сохранение прогресса.** В Render задайте `SUPABASE_URL` и `SUPABASE_SECRET_KEY` через Environment; `.env` в репозиторий не загружается. Данные находятся в Supabase, постоянный диск Render больше не нужен. План `starter` оставлен прежним; изменение тарифа не выполнялось.
