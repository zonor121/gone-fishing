# Миграции Supabase

Каталог содержит упорядоченные, идемпотентные миграции для **уже развёрнутых**
Supabase-проектов. Свежая установка может сразу выполнить `db/supabase.sql` целиком —
там уже всё состояние; миграции нужны, чтобы не пересоздавать схему на рабочем проекте.

## Правила

- Имя файла: `NNN_краткое_название.sql`, нумерация сквозная, применяется строго по порядку.
- Каждая миграция — один атомарный оператор `CREATE OR REPLACE FUNCTION public.fishing_api`
  (плюс REVOKE/GRANT/NOTIFY), поэтому повторный запуск безопасен: функция просто
  пересоздаётся, данные таблиц не трогаются. Миграция, меняющая схему, добавляет ещё
  идемпотентный `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` перед функцией (см. 003).
- Итог функции в миграции `NNN` обязан совпадать с `db/supabase_api.sql` после применения
  миграций `001..NNN`. Это сверяется тестом `test_migrations_match_api` (tests/test_supabase.py).
- Имя миграции описывает смысл изменения, а не дату: по списку файлов видно историю экономики.

## Как применить

1. Supabase Dashboard → **SQL Editor** → New query.
2. Вставьте содержимое `001_weighted_catch_price.sql` → **Run** (ожидается `Success. No rows returned`).
3. Повторите для `002_boat_price_10000_and_spin_bait.sql` и `003_bells_200.sql`.
4. Проверка: `SELECT fishing_api('health');` → `{"ok":true}`.

Альтернатива — Supabase CLI: `supabase db execute -f db/migrations/001_weighted_catch_price.sql`
и т.д. Приложение на Render менять не нужно: новый код `server.py` совместим с обоими
состояниями функции, но возвращает ожидаемые поля только после применения миграций.

## Журнал

| # | Файл | Что меняет |
|---|------|------------|
| 1 | `001_weighted_catch_price.sql` | Награда за рыбу зависит от веса: 0.75× цены при `min_kg` до 1.75× при `max_kg`, линейно с округлением вверх. Лодка ещё 6 000 ₽, блесна расходуется на каждом забросе. |
| 2 | `002_boat_price_10000_and_spin_bait.sql` | Лодка подорожала до 10 000 ₽ (проверка, списание, сообщения, `boat_price` в конфиге). Блесна расходуется только в 25% забросов: `random() < 0.25`; ответ `cast` содержит `bait_kept=true`, когда наживка не потрачена. |
| 3 | `003_bells_200.sql` | Колокольчики за 200 ₽: колонка `player.bells_owned`, `buy` с `item='bells'` (409 при повторе, 400 при нехватке денег), `bells_owned` в `state`, `bells_price=200` в `config`. Звон при поклёвке — на клиенте. |
